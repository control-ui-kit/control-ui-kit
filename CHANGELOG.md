# Changelog

All notable changes to `control-ui-kit/control-ui-kit` will be documented in this file

## Unreleased

### Added

- `x-modal`, and through it `x-modal-dialog`, `x-modal-confirmation` and `x-modal-action`, accepts a `scroll` attribute (theme: `modal.scroll`, default `panel`) choosing how a modal taller than the viewport scrolls. `panel` scrolls the whole panel and is safe for arbitrary slot content; `body` (the default for the dialog, confirmation and action modals, which own their own markup) scrolls only the content region so the footer buttons stay pinned in view; `clip` clips the overflow, which is the closest to the old behaviour and is there as an escape hatch. The three modes are the theme keys `modal.scroll-panel`, `modal.scroll-body` and `modal.scroll-clip`, appended to the panel's own classes. Note that `scroll` names a key suffix rather than a class, so unlike a style attribute it has no `none` - that is why the third mode is `clip` - and anything other than `panel`, `body` or `clip` throws a `ControlUIKitException`.
- The modal geometry is now themeable, like every other component in the kit, rather than hardcoded in the published views. `x-modal` accepts `overlay` (theme: `modal.overlay`) for the full-screen box the modal is centred in and `panel` (theme: `modal.panel`) for the panel itself; `x-modal-action` also accepts `body` (theme: `modal.body`), `footer` (theme: `modal.footer`), `form` (theme: `modal.form`) and `title-class` (theme: `modal.title`); and `x-modal-dialog` / `x-modal-confirmation` accept `body`, `title-class` and `footer-class` - `title` and `footer` there are the names of slots, so the style attributes cannot share them. All of them accept `none` and the `...` append prefix as usual. `class` and `style` on `x-modal` have never had any effect, because the template's own hardcoded `class=` precedes `{{ $attributes }}` and HTML5 keeps the first of a duplicated attribute; `overlay=` and `panel=` are the supported replacement.
- **Republish the theme file.** `modal` gains eight new keys, and a published `config/themes/default.php` replaces the package's `modal` array wholesale (`mergeConfigFrom` is a shallow `array_merge`, and under `config:cache` the merge is skipped altogether), so an app that has published the theme and does not republish it will throw `Config key not found [themes.default.modal.overlay]` on every modal.

- `x-tabs` accepts `position="side"` (theme: `tabs.position`, default `top`) to lay the tab headings out in a column to the left of the panels rather than in a row above them. The heading column is sized by `side-width` (theme: `tabs.side-width`, default `min-w-48`) and never shrinks, so heading text does not wrap - pass a `min-w-*` class for a floor that long headings can still push wider, or a `w-*` class to pin the column. `side-gap`, `side-spacing` and `side-heading` style the gap between the two columns, the spacing between the headings, and the headings themselves (the default swaps each heading's bottom border for a left one, so the active heading is marked down its left-hand edge). Below `tabs.breakpoint` a side tabs block collapses to the same native select as a top tabs block, with the panels beneath it. Any `position` other than `top` or `side` throws a `ControlUIKitException`.
- `x-error`, and through it every field, accepts an `alpine-errors` attribute naming the Alpine object a form's errors arrive in - `<x-field-slot name="description" alpine-errors="ui.expenseErrors">`. A form posted over XHR gets its 422 back as JSON and is never re-rendered, so Laravel's error bag stays empty and the field had nothing to show; pointing it at the response body instead renders the message in the same place, in the same style, as a server-side one. The object is read by field name, matching a Laravel 422 body's `errors`, and either a string or the first entry of an array is displayed. Without the attribute nothing changes.

- `x-tabs` accepts a `select-spacing` style attribute (theme: `tabs.select-spacing`, default `pb-2`) for the gap below the native select a tabs block collapses to under its breakpoint. Only the headings row above the breakpoint is spaced by the panels themselves, so without this the select sits flush against whatever the open panel starts with - most visibly when tabs are nested, where the outer select and the inner one end up touching. It applies to the select's wrapper, so it costs nothing above the breakpoint where that wrapper is hidden.
- `x-table-pagination` accepts `:show-limit="false"` (theme: `table-pagination.show-limit`, default `true`) to render the page buttons and the results count without the "Display #" per-page selector. The selector carries its own `<form method="get">`, which cannot be nested inside another form - the parser drops the inner tag and the outer form adopts the select, so it stops working and starts posting a stray `limit` field - so a paginated table that lives inside a form has to be able to turn it off. Livewire tables are the usual case, since they page through `wire:click` and have no use for a GET form.
- `x-tooltip` accepts a `width` style attribute (theme: `tooltip.width`, default `max-w-[min(20rem,calc(100vw-1rem))]`) so the maximum width of the tooltip bubble can be themed or overridden per tooltip. Pass `width="none"` to remove the constraint.
- `x-alert` now supports an optional close button, which is rendered when `close-button-url` is set. The icon and colour can be overridden with `close-button-icon` (theme: `alert.close-button-icon`, default `icon-close`) and `close-button-color` (theme: `alert.close-button-color`, defaults to the resolved `icon-color`); both accept `none`. Any other attribute prefixed with `close-button-` is passed through to the close button with the prefix stripped, so it can be wired up to Alpine or Livewire - for example `close-button-x-on:click.prevent="show = false"`.

### Changed

- The title of a scrolling modal no longer scrolls with its content. `x-modal-dialog`, `x-modal-confirmation` and `x-modal-action` put the title alert and the content in the same scroll container, so scrolling a long modal carried the title off the top of the panel and left nothing to say what the modal was for. The title is now a pinned `shrink-0` region of its own (theme: `modal.title`, default `shrink-0 px-4 pt-4`), a sibling of the scrolling body rather than its first child, so a `scroll="body"` modal - the default for all three - pins the title above and the footer below and scrolls only the content between them. Spacing is unchanged: the title's `pt-4` and the body's `p-4` reproduce exactly what the old `p-4` wrapper and its inner `pt-4` / `mb-4` gap produced. `x-modal-action` emits the region only when it is given a `title` slot, as before. A modal set to `scroll="panel"` or `scroll="clip"` has no inner scroll container, so its title is unaffected.

- **BREAKING:** Renamed the theme HTML attribute from `data-theme` to `data-ui-theme` to avoid conflicts with browser extensions (e.g. Loom) that rewrite the generic `data-theme` attribute and break theme styling. Generated theme CSS now targets `:root[data-ui-theme="<name>"]`.
  - Migration: update your `<html>` tag from `data-theme="<name>"` to `data-ui-theme="<name>"`, and regenerate (or find/replace `data-theme` → `data-ui-theme` in) any already-generated theme CSS files.

### Fixed

- `x-input-autocomplete`, and so `x-field-autocomplete`, stopped responding entirely: clicking the field did nothing useful, and in some browsers the malformed markup was enough to knock the page onto `about:blank`. The component's `x-data` is a single-quoted attribute, and `value` and `filter` had been switched to `@js()`, which wraps a string in **single** quotes - it is built for the double-quoted `x-data` every other input uses. The first of those quotes closed the attribute at `value:`, so the browser parsed the rest of the object as a run of loose attributes and Alpine was handed `Components.inputAutocomplete({ value:` to evaluate. Both values are now encoded with `@json(... JSON_HEX_APOS | JSON_HEX_AMP | JSON_UNESCAPED_SLASHES)`, like every other value in the same object, which keeps an apostrophe inside the attribute rather than ending it. The option data in `x-init` gained `JSON_HEX_AMP` for the same reason - an option label containing a literal `&amp;` was being entity-decoded back by the HTML parser before Alpine ever saw it. The other Alpine inputs are unaffected: their `x-data` is double quoted, where `@js()` is correct.

- A modal taller than the viewport was unreachable: its lower half was clipped off the bottom of the screen with no way to scroll to it. Three separate things caused that. The overlay was `fixed top-0 inset-x-0 h-72` - a hard 18rem box rather than a viewport-sized one - with no `overflow-y-auto`, so nothing in the modal could ever scroll; the panel was `absolute top-1/2` inside that box with no `-translate-y-1/2`, so rather than being centred it hung downward from a fixed 9rem below the top of the viewport and grew off the bottom; and the panel was `overflow-hidden` with no `max-h-*`, so anything that did overflow was clipped permanently. `items-top` on the overlay was doing nothing either - it has never been a Tailwind utility, so `align-items` silently fell back to `stretch`. The overlay is now `fixed inset-0 ... overflow-y-auto p-4 sm:p-6` and the panel `my-auto max-h-full`, so a short modal is centred, a tall one is capped to the viewport and scrolls internally per the new `scroll` attribute, and the top of an overflowing panel is never clipped. The panel is also `w-full` rather than `w-11/12 sm:w-full`, since the overlay now supplies the gutter, and carries `role="dialog" aria-modal="true" tabindex="-1"`.
- The page behind an open modal stayed scrollable - there was no scroll lock anywhere in the package. Opening any modal now sets `overflow: hidden` on the document and compensates for the width of the scrollbar it removes with a matching `padding-right`, so there is no layout shift on open or close, and restores the original inline values on close. The lock is reference counted, so `x-modal-action` handing off to its results modal keeps the page locked across the handover and unlocks once, and it is released on Alpine teardown as well as on close - a Livewire re-render that removes an open modal does not leave the page stuck. Closing a modal also returns focus to whatever element opened it, which was previously abandoned on a `display: none` element. Every close path - the close event, Escape, a backdrop click, the action modal's cancel button and its submit handler, and a consumer's own footer button - goes through the same `show = false`, so all of them are covered.
- Every modal opened through `openModal()` silently lost its width. `maxWidth` is already resolved to a class by the component, and `openModal()` ran it through the template's `width()` switch a second time, where an already-resolved value matched no case and fell through to `default:` - so a `max-width="2xl"` modal came out `sm:max-w-xl` the moment it was opened. `width()` now returns an already-resolved value unchanged, which also means the resolved `detail.width` that `openDialog()` and `openConfirm()` have always sent, and that nothing read, is honoured. `x-modal-action` additionally never resolved `maxWidth` at all, so its panel carried a literal `2xl` class until `openModal()` ran, and its `width()` was missing the `3xl` and `4xl` cases that `x-modal` has had; both are fixed, and the shared resolution now lives in one trait and one Blade partial rather than in four copies.

- A native `x-input-select` (and so the select an `x-tabs` block collapses to below its breakpoint) drew the browser's own picker indicator, which sits hard against the right-hand border and ignores the `pr-10` that `button-padding` reserves for it - so it looked nothing like the chevron on every other select, which sits `px-2.5` in behind a `border-l` divider. The native select is now `appearance-none` inside a `relative` wrapper that carries `button-width`, with the theme's `icon-closed` chevron positioned against it by the same `icon-*` styles the custom select uses. `class` and the visibility directives (`x-show`, `x-cloak`, `x-transition*`) are applied to that wrapper - `class` to match where the custom select puts it, and the rest because the chevron is a sibling of the select, so hiding only the select would leave its chevron behind. Everything else, `x-model`, `wire:model`, `required` and any other attribute, stays on the `<select>` where it was.

- `x-table-cell` dropped its own padding when given an `x-text` or `x-html`. Alpine writes to whatever element carries the directive, and the cell put every attribute it was handed on the `<td>` - so the first evaluation replaced the `<td>`'s contents, padding div included, and the column sat flush against the cell edge while its heading kept its padding. Both directives are now lifted off the cell and carried by a `span` where the content goes, inside the padding div, the pill, or the link, so alignment survives and `prefix`, `suffix`, `icon` and `image` are no longer wiped out either.

- `x-field-slot` accepted a `tooltip` and never rendered it. Unlike the other fields it has no input of its own to hand to `x-form-field`, so it renders its layout directly - and `x-form-field` was the only thing defaulting `tooltip-type`, `tooltip-icon` and `tooltip-position` from the theme. The layout got a tooltip with an empty type, and the type is what its template gates the tooltip on, so it was accepted and then dropped. The three layouts now default those three settings from the theme themselves, exactly as `x-form-field` does, and decode entities in the tooltip text the same way.

- A field tooltip icon was vertically centred against the whole label, so on a field whose label wrapped onto a second line (common for a checkbox or toggle, where the label carries all of the text) the icon dropped below the input it belonged to. The icon's wrapper in all three field layouts is now `self-start min-h-[2rem] flex items-center`, which centres it in the same `min-h-[2rem]` band the layout's `slot` style gives the input, so it stays level with the input no matter how many lines the label runs to. A single-line label is unaffected, because the band and the label row are the same height.
- `x-tooltip` never wrapped, so a long tooltip (for example a sentence of field help text) rendered as a single line wider than the viewport and ran off both edges of the screen. The theme's `tooltip.other` was `whitespace-nowrap`; it is now `whitespace-normal wrap-break-word`, and the bubble is capped by the new `tooltip.width` style. Because a wrapped bubble is wide enough to overhang the trigger, the teleported tooltip now measures itself on show and shifts along its cross axis (horizontally for `top`/`bottom`, vertically for `left`/`right`) to keep an 8px margin inside the viewport, with the arrow counter-shifted by the same amount - clamped to the bubble's half-extent - so it stays pointing at the trigger. The teleported wrapper is also anchored at `top:0;left:0` and positioned entirely through `transform: translate(...)`, rather than being offset with `top`/`left`: a `position: fixed` box offset by `left` only has `100vw - left` of available width, so a tooltip on a trigger near the right edge of a narrow screen shrank to its min-content width (one word per line) before any of the width rules above could apply.
- `x-input-otc` / `x-field-otc` digit boxes did not shrink with the viewport, so on a narrow phone the row ran off the side of its container. The boxes are a fixed `width` in a flex row, and three separate things stopped that row from shrinking: the component's wrapper is dropped into the field layout's flex slot, where its automatic minimum size (`min-width: auto`) resolved to the combined width of the digits; the `<fieldset>` is given `min-inline-size: min-content` by the UA stylesheet, holding it at that same width; and each digit is itself a flex item whose automatic minimum size kept it at its own width, so `flex-shrink` never reduced it. All three now carry `min-w-0`, hardcoded in the template rather than themed so that overriding `fieldset` or `other` cannot drop them. Removing any one of the three brings the overflow back.
- `x-input-otc` / `x-field-otc` posted only the first digit of a typed code. The component watched all six boxes with a single `$watch('digit_1, digit_2, ...')`; Alpine compiles a watch expression to `__self.result = <expression>` and assignment binds tighter than the comma operator, so the watched value was `digit_1` alone and Alpine's `watch()` skipped the callback whenever it was unchanged. Typing into any box but the first therefore never re-ran `updateValue()`, leaving the hidden field holding whatever it held after the first box was filled. It now registers one watcher per digit. A pasted or autofilled code was never affected, because `populateNext()` fills every digit synchronously before the `digit_1` callback runs.
